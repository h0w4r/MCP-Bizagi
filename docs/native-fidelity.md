# Native fidelity policy

`NativeFidelity.Compare` reads every leaf in an unencrypted `.bpm` archive,
including the entries inside each `.diag` archive. It does not export BPMN or
reconstruct a native model from a reduced graph. Binary content is compared
byte-for-byte; XML is compared as ordered elements, expanded attribute names,
content, comments and processing instructions. XML declarations, attribute order
and indentation-only whitespace are not treated as model edits. Namespace bindings
are conservatively retained because unknown content can include QName-valued
attributes; changes in those bindings are reported rather than guessed harmless.

`NativeWorkflows.ApplyNames` requires a matching source SHA-256, snapshots the
input, edits a new native file, and verifies every requested ID/name in a fresh
worker. It then runs this comparator before marking the operation completed.
`native_save_copy` uses the same route with no requested edits.

## Explicitly classified engine behavior

Current source policy identifier: `native-v5-content-with-explicit-engine-metadata-v2`.
Released 0.4.0-alpha.1 evidence used `v1`. The `v2` extension classifies native
definition-root audit timestamp updates and embedded attachment runtime path
relocation only when the referenced native archive leaf exists under the owning
element. Binary changes, linked-file paths and unknown XML content remain exact.
User-embedded `.xml` files are opaque binary payloads, not native metadata.

| Classification | Narrow allowance |
| --- | --- |
| `requested_name_change` | A supplied native identity and its exact requested name |
| `modification_timestamp` | Recognized native modification timestamps; both values must parse as dates |
| `engine_process_timestamp` | Native XPDL `WorkflowProcess/ProcessHeader/Created`, regenerated by the installed serializer |
| `modification_audit_appended` | Appended native modification records with date and user; removal/reattribution is rejected |
| `transparent_text_background_materialized` | Missing native graphics text background materialized as transparent ARGB `16777215` |
| `attachment_runtime_path_relocated` | Embedded reference moves between private engine scratch folders; owning element/file identity and actual archive bytes remain checked |

These differences are **reported**, not presented as byte equality. Everything
else fails the preservation gate, including removed entries, changed binary
attachments, unrelated XML properties and changes in unknown content.
The source file is not replaced. Rejected outputs and `native-fidelity.json`
remain private diagnostic artifacts and cannot be adopted through artifact references.

## What a pass does not establish

- Independent visual compatibility inside Modeler.
- Support for every element type, attachment producer or historical native format.
- Preservation of application state outside the archive, such as cloud revisions.
- Complete BPMN interchange equivalence: XML export is a separate, lossy projection.
- General-purpose geometry, structural, attribute or resource editing.

Basic, nested/multi-diagram, configured simulation, and the documented extended
attribute/attachment no-op corpora have run through the real MCP/native circuit.
Broader combinations still need their own native acceptance. Comparator unit tests
exercise unknown/binary-content rejection but do not replace those engine runs.

## Artifact references

Completed writers return `artifact:<operation-id>:model.bpm` or
`artifact:<operation-id>:edited.bpm`. Native tools accept these references in
their `path` argument. Resolution checks the completed journal and reads only
the designated native file through the same reparse/path protections.
This permits MCP-only chaining without opening private state directories as an
arbitrary filesystem API. Ordinary paths must still remain inside the workspace.
